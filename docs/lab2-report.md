# Лабораторная № 2: реализация MCP и агента

## Что реализовано

`app/mcp/` — отдельный stdio-сервер на официальном SDK, клиент, строгие контракты,
проверка результатов и подпись доверенного контекста записи. `app/agent.py` — нативный
цикл выбора инструментов; `app/tool_data.py` — погода и расписание.
`app/reminders.py` — состояния в PostgreSQL; `app/handlers/reminders.py` — интерфейс;
`app/reminder_delivery.py` — доставка без вызовов модели.

При запуске бот получает инструменты и схемы через MCP. Соединение и дочерний процесс
живут вместе с приложением. Сервер получает только подключение к БД, источник расписания
и временный ключ подписи; Telegram, OpenRouter и management key ему не передаются.
При сбое MCP обычный диалог остаётся доступен. Для восстановления процесса MCP нужен
перезапуск бота; автоматическое переподключение пока не реализовано.

Инструменты: `get_weather(city)`, `get_schedule(date)`, `add_reminder(text, remind_at)`.
Ресурс: `schedule://current-week`, понедельник–воскресенье в настроенной зоне.
Схемы доступны через discovery; неизвестные поля отклоняются. `request_clarification` —
локальное действие агента для уточнений, а не четвёртый MCP-инструмент.

В диалоге, учёбе и музыке используется native tool calling. Перевод, явный web-поиск
и температурные эксперименты сохраняют прежний путь. На запрос: максимум три LLM-раунда,
два MCP-вызова и 90 секунд агентного цикла. Дополнительные данные инструмента учитываются
в лимите контекста: сначала удаляется старый контекст; если данные всё равно не помещаются,
цикл завершается с предложением сократить запрос. JSON результата не обрезается.
Каждый выполненный LLM-раунд отдельно учитывается в статистике, включая неизвестную стоимость.

## Напоминания и доверие

Кнопка «Напоминания» позволяет задать IANA-зону, ввести текст и дату, посмотреть список,
отменить ожидающую запись. Можно попросить напоминание обычным текстом в агентном режиме.
Модель только готовит заявку. Кнопка подтверждения связана с неизменяемой заявкой в БД
на пять минут; пользователь берётся из Telegram, не из аргументов модели.

Хост подписывает владельца, ID заявки, хеш аргументов и короткий срок запроса в `_meta`.
Сервер повторно проверяет подпись, подтверждение в БД и совпадение аргументов.
Одна подпись без подтверждённой записи не разрешает действие. Повторы возвращают тот же ID.
После перезапуска новая пара хост/сервер использует новый ключ, а сохранённая заявка
подтверждается по прежней кнопке до истечения срока.

Обрабатываются переходы часов. Для неоднозначного времени в свободном запросе агент
просит уточнение; точное ISO-время со смещением можно ввести через интерфейс напоминаний.
Профили, расписание и результаты инструментов не могут подтверждать запись.
Тексты напоминаний не попадают в аудит. `/why` показывает действие, безопасные аргументы
(город, дату или время), статус и фиксированное объяснение без скрытых рассуждений.

Доставка — расширение продукта сверх второй лабы. Исполнитель проверяет БД раз в 5 секунд.
Просрочка больше минуты помечается как задержка с исходным временем; больше суток — `missed`.
Захват имеет отдельный токен. Сетевая неопределённость или прерванная отправка → `unconfirmed`,
без автоматического дубля. Только явный Telegram 429 допускает один повтор, если ожидание
не больше 10 секунд. Блокировка бота → `blocked`. Отменить уже отправляющуюся запись нельзя.
Завершённые записи хранятся 30 дней, аудит — 90; активные напоминания сохраняются.

## Источники данных и настройка

`SCHEDULE_PATH` задаёт JSON вида `{"YYYY-MM-DD": [{"start":"10:00","end":"11:00",
"title":"Занятие","location":"Аудитория"}]}`. Предел файла — 64 КиБ, 366 дат, 30 занятий
на дату. Путь выбирает оператор, не пользователь и не модель. В контейнере это путь внутри
образа или заранее смонтированного файла. Личное расписание не добавлять в Git.
`SCHEDULE_TIMEZONE` — зона расписания; она не заменяет личную зону `/timezone`.
В комплекте — явно вымышленные занятия 10–11 января 2030 года.

Для погоды выбран [Open-Meteo](https://open-meteo.com/en/docs): фиксированные HTTPS-адреса,
Цельсий и км/ч, время и зона наблюдения, ссылка на источник. Геокодирование использует
[официальный API](https://open-meteo.com/en/docs/geocoding-api). При нескольких результатах
возвращаются страна и регион; первый город не выбирается. Пустой результат отличается
от ошибки API. Перенаправления отключены, ответ ограничен 64 КиБ, общий срок — 15 секунд.

## Проверки и их границы

Автономно проверяются реальные MCP-обмены в памяти и отдельном stdio-процессе:
discovery, ресурс, строгие аргументы, структурированные результаты, отказ без подписи,
подмена владельца/аргументов/ключа и истечение подписи. БД в этих тестах заменена заглушкой.

Отдельные PostgreSQL-тесты используют изолированные Docker-контейнеры: настоящий
`python -m app.mcp` отклоняет неподтверждённую запись и создаёт одну запись при четырёх
одновременных повторах. Проверка агента с пулом из одного соединения обнаруживает
случайные повторные захваты пула; она также сверяет отдельный учёт двух LLM-раундов,
у одного из которых цена неизвестна. LLM в этом тесте заменена заглушкой.

Проверки агента: прямой ответ без MCP, уточнение, два чтения и финальный ответ,
игнорирование моделью запрета новых вызовов, пакет лишних вызовов, подмена owner,
подготовка без записи, отсутствие зоны, большой результат, инструкции внутри результата
и общий тайм-аут. Проверки доставки: обычный ответ Telegram, неопределённый тайм-аут
без повтора, ограниченный повтор 429, блокировка, отмена во время отправки.

Погодные данные, Telegram и LLM в автономных тестах имитируются. Реальные запросы,
качество маршрутизации выбранной модели и фактическая доставка пользователю автоматически
не проверялись. Платные эксперименты агент не запускает.

Для версии `44b8b02` [CI](https://github.com/bimo0o/tg_ai_helper/actions/runs/39852506559)
успешен на Windows, macOS и Linux, включая девять PostgreSQL-тестов. Локальный прогон:
382 passed, 10 skipped. При самопроверке дополнительно уточнены условия маршрутизации:
обычный вопрос не должен требовать город или часовую зону; неоднозначный город
останавливается в коде с выбором пользователя, без автоматического следующего LLM-вызова.
Дата без времени в ручном вводе отклоняется, а не превращается молча в полночь.

## Независимая проверка MCP Inspector

Используйте отдельную тестовую БД, применив миграции; не подключайте Inspector к рабочей БД.
В окружении Inspector задайте только тестовые `POSTGRES_HOST/PORT/DB/USER/PASSWORD`,
`SCHEDULE_PATH`, `SCHEDULE_TIMEZONE` и временный `MCP_SIGNING_KEY` — 64 hex-символа
случайных 32 байтов. Не используйте для него Telegram- или OpenRouter-ключ.
Обычный запуск бота сам генерирует этот ключ; в `.env` он не требуется.

Согласно [официальной инструкции Inspector](https://modelcontextprotocol.io/docs/tools/inspector),
после активации `.venv` запустите из корня:

```text
npx @modelcontextprotocol/inspector python -m app.mcp
```

Проверьте Tools → три инструмента с входными/выходными схемами; Resources → текущая неделя;
`get_schedule` для `2030-01-10`; пустую дату; прямой `add_reminder` без доверенного контекста
должен вернуть отказ. Интерактивная проверка Inspector ещё не выполнена.

Нужны исходный набор, запуск пользователем на выбранной модели, анализ ошибок и повтор
после одного контролируемого изменения. Затем — ручная проверка Inspector и Telegram,
финальная фиксация результатов и тег `lab2` после приёмки.

AI использовался для проектирования, кода, тестов и документации. Исправленное предложение AI:

`::timestamptz` и повторён интеграционный прогон. Результаты тестов не заменяют защиту
и понимание владельцем проекта схемы доверия и компромисса доставки без слепых дублей.
