# Авторская проверка маршрутизации

`lab2-routing-authored.json` — собственный дополнительный набор, а не отсутствующий
`lab2-routing.json` из методички. Пользователь подтвердил, что исходного набора не будет.
Его официальные метрики не заявляются.

Условия зафиксированы до прогона: 10 января 2030, 10:00, `Europe/Moscow`; 3 запроса
о погоде, 3 о расписании, 3 о напоминаниях, 2 без инструментов, 1 на уточнение.
Допустимые варианты аргументов города перечислены заранее, а не подбираются после ответа.
Сравнение времени принимает эквивалентные UTC-моменты; лишние поля вроде `owner` запрещены.

Измеряется **первое нативное решение** модели и его аргументы. Используются те же Agent,
промпт режима «Диалог» и схемы, обнаруженные через настоящий MCP в памяти.
Данные чтения — фикстуры; уведомления не создаются в БД и не отправляются.
Последующее оформление ответа исключено из измерения: на сценарий максимум один
реальный LLM-запрос, остальные шаги имитируются. Это не сквозной тест погоды или доставки.

## Запуск

Из корня проекта после установки зависимостей, с активной `.venv`:

```text
python -m app.routing_evaluation
```

Без `--execute` API не вызывается, `.env` не читается; проверяются набор, условия и SHA-256.
Для настоящего прогона пользователь запускает:

```text
python -m app.routing_evaluation --execute --output .evaluation/routing-v1.json
```

До 12 платных запросов. Настройки берутся из `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`,
`LLM_TIMEOUT_SECONDS`, `MAX_OUTPUT_TOKENS`; фиксированная температура по умолчанию 0.3.
CLI не читает модель из БД админки: при необходимости укажите тот же точный ID через
`--model`, а температуру — через `--temperature`. Настройки неизменны внутри одного прогона.
Профили и история пользователей не используются.

На сервере, из `/root/tg_ai_helper`, можно передать набор в контейнер через stdin:

```bash
docker compose --profile cloud exec -T bot python -m app.routing_evaluation \
  --dataset /dev/stdin --execute --output /tmp/routing-v1.json \
  < docs/evaluation/lab2-routing-authored.json
```

Путь `/tmp` доступен пользователю контейнера. Для выгрузки отчёта:

```bash
docker compose --profile cloud cp bot:/tmp/routing-v1.json ./experiment-results-routing-v1.json
```

Выходной файл проверяется до платных вызовов, существующий отчёт не перезаписывается.
Результаты дописываются после каждого сценария. Отказ доступа, нехватка средств или 429
останавливают прогон; такой отчёт отмечен как неполный. Неизвестная стоимость не выдаётся
за нулевую. Локальная `.evaluation/` исключена из Git.

## Разбор результата

JSON содержит таблицу ожидаемых/фактических действий и аргументов, проверку рабочего
сценария, фрагмент ответа, время, usage и стоимость; также модель, температуру, бюджет,
контрольное время и хеш набора. Учебный ориентир: не меньше 10/12 действий и 8/9 аргументов
на этом авторском наборе. Это не утверждение о прохождении отсутствующего исходного набора.

Разберите ошибки, измените ровно один элемент (например, условие промпта), повторите
с тем же набором и настройками в `routing-v2.json`. Сохраните оба отчёта; сначала
сравнивайте ошибочные случаи, затем проверьте отсутствие регрессии остальных.
Автономные тесты механики используют подставную модель: их 12/12 не являются
оценкой качества реальной модели. Платный прогон агент не запускал.
