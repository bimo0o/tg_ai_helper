# Сравнение температур в админ-панели

[Описание продукта](../README.md) · [Эксплуатация](operations.md) · [Лабораторные](labs.md)

## Запуск

1. Откройте «Админка» или `/admin`, затем «Тест температур».
2. Выберите «Запрос для лабораторной», «Искусство: концепция картины» либо «Свой запрос».
3. Для своего запроса отправьте один текст. Он только подготавливает тест и не вызывает модель.
4. Проверьте запрос, модель и ограничения. Нажмите «Запустить 12 платных запросов».
5. Дождитесь сводки и нажмите «Скачать отчёт».

Стандартный запрос использует режим «Учёба»: модель объясняет list/tuple через бытовую
аналогию, раскрывает её ограничения и учитывает изменяемые объекты внутри кортежа.
Аналогии с коробками, контейнерами и покупками запрещены. Это оставляет выбор образа
и формулировок, сохраняя проверяемую учебную задачу. Полный запрос хранится в
`app/experiment_spec.py` и одинаков для админки и CLI. В предпросмотре виден точный текст.
Свой запрос использует режим «Диалог». Web-поиск и музыкальный профиль выключены.

Художественный тест тоже использует «Диалог». Запрос: придумать концепцию картины
для выставки «То, чего ещё не было», самостоятельно выбрав сюжет, технику и палитру.
Три строки содержат название, описание с идеей и способ исполнения. Такой запрос
оставляет широкий выбор вариантов: сравнивайте образы, материалы и композиционные идеи
внутри каждой температуры, а не только замену отдельных слов. Формат строк проверяется
автоматически; содержательные различия и ограничение 120 слов — вручную.

Для художественного и учебного теста условия одинаковы во всех повторах: приложение
не добавляет случайные подсказки и не просит специально менять ответ при высокой температуре.
Можно ожидать большей повторяемости при низкой температуре, но одинаковые ответы при
`0` и сильно разные при `1` не гарантируются. Все полученные результаты сохраняются.
Подтверждение запуска действует 15 минут. Доступ при каждом действии проверяется по владельцу в БД.

## Условия сравнения

Выполняются четыре группы: `0.0`, `0.3`, `0.7`, `1.0`, по три вызова в каждой.
Модель, запрос, системные инструкции, few-shot и лимит ответа фиксируются при подготовке.
Каждый вызов получает одинаковые сообщения без предыдущих ответов. История и настройки обычного диалога не меняются.
Если таймаут сервера изменился после подготовки, тест нужно подготовить заново.

Запросы идут последовательно, автоматических повторов ошибок нет. Каждый фактический вызов учитывается в общей статистике `/admin`.
Различия между провайдерами OpenRouter и собственная недетерминированность модели также могут влиять на ответы: эксперимент не изолирует эти факторы.

## Результаты

- **Сводка в Telegram:** успехи, число разных текстов внутри каждой группы, длины и известная стоимость с покрытием учёта.
- **HTML:** таблица всех запусков и полные ответы для чтения в браузере и демонстрации.
- **JSON:** метаданные, инструкции, ответы, токены, время, стоимость, ошибки и признаки достижения лимита.

Различие текстов проверяется точным сравнением. Эта метрика не оценивает смысловую близость, правильность или полезность.
Для стандартного лабораторного запроса отдельно проверяются три непустые строки с нумерацией `1.`, `2.`, `3.`.
Ограничение 120 слов, корректность аналогии и отсутствие запрещённых образов проверяются вручную.
Содержание и соответствие задаче оцениваются человеком. Для своего запроса автоматический критерий формата не задан.
Совпадения, ошибки и обрезанные ответы сохраняются; удачные результаты не отбираются.

## Отмена и хранение

«Отменить тест» останавливает последующие вызовы. Запрос, уже отправленный провайдеру, может завершиться и быть оплачен; его результат сохраняется.
Одновременно допускается один выполняющийся тест владельца. Повторное нажатие запуска не создаёт второй прогон.
Результаты сохраняются в PostgreSQL после каждого ответа и доступны через «Последний тест» или кнопки сообщения с конкретным тестом.

После перезапуска платные вызовы автоматически не продолжаются. Если процесс оборвался без завершения, просроченная аренда выполнения помечает тест прерванным.
Это может занять до таймаута одного запроса плюс 60 секунд с последнего продления аренды.
Во время аварии результат текущего вызова и его стоимость могут остаться неизвестными.
Сохранённые результаты хранятся 30 дней. Чтение исключает истёкшие записи сразу, физическая очистка выполняется каждый час.
Скачанные файлы содержат введённый запрос и ответы; храните их с учётом содержания.

## Демонстрация на защите

Сначала назовите признаки хорошего ответа, затем запустите один и тот же запрос для всех температур и покажите все результаты.
Для заметной вариативности подходит задача с несколькими допустимыми формулировками, например:

> Предложи три разных названия для melodic techno трека о ночном городе. Для каждого дай короткое объяснение. Не используй слово «ночь».

Арифметический вопрос или перевод короткой фразы могут давать одинаковые ответы при любой температуре.
Высокая температура не гарантирует ни отличий, ни улучшения качества. Не стоит обещать на защите, что каждый следующий ответ обязательно будет отличаться.
Сравните повторяемость, структуру, полноту и соблюдение ограничений; сохраните наблюдения вместе с исходными результатами.

Для первой лабораторной остаётся доступен [ручной CLI-эксперимент](lab1-experiment.md).
Админ-панель предоставляет дополнительный интерфейс сравнения; демонстрация `/reset`, анализ и оформление отчёта остаются отдельными пунктами сдачи.
